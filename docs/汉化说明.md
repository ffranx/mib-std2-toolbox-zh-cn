# MIB STD2 Toolbox 汉化说明

对象：`olli991/mib-std2-pq-zr-toolbox` v1.5.1（`MIBSTD2_Toolbox-v1.5.1.zip`）
适用：MIB2 **Standard** PQ/ZR（TechniSat/Preh），例如 `MST2_CN_VW_PQ_P0480T` 这类国行机器。

---

## 一、能汉化到什么程度

绿菜单（GEM）里所有可见文字只有两个来源，都在 `.esd` 纯文本里：

| 位置 | 语法 | 说明 |
|---|---|---|
| 菜单项名字 | `screen <本屏名> <父屏名>` | 第一行就是菜单里显示的那一条 |
| 屏内文字 | `label "..."` | `keyValue` / `script` / `choice` 的文案都是它 |

v1.5.1 一共 **23 个 `.esd`**、**321 条不重复 label**（含大量车辆适配通道名）。
`label` 汉化是安全的；`screen` 名汉化是**实验性**的（见第四节风险）。

---

## 二、目录

```
mib2-zh\
├─ src\                      v1.5.1 原版（解压后，未改动）
├─ tools\localize_esd.py     汉化脚本
├─ tools\check_esd.py        .esd 体检工具（字符格式十项检查）
├─ zh_map.json               映射表（可继续往里加）
├─ out\                      产物 A：只汉化屏内文字（UTF-8，保留中文全角标点）
├─ out-safe\                 产物 B：同 A，但全角标点/全角数字压成半角（字形最保险，推荐）
├─ out-screens\              产物 C：B + 菜单项名字也汉化（实验性）
└─ README-汉化说明.md
```

产物目录结构与原包完全一致，可直接当 SD 卡根目录用（`metainfo2.txt` 在根）。

## 三、跑法

```powershell
$py = 'C:\Users\12321\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'

# A. 只改屏内文字（UTF-8）
& $py .\tools\localize_esd.py --src .\src --out .\out --map .\zh_map.json --encoding utf-8

# B. 连菜单项名字一起改（实验性）
& $py .\tools\localize_esd.py --src .\src --out .\out-screens --map .\zh_map.json --encoding utf-8 --screens

# C. 想试 GBK 编码（部分 QNX/J9 环境把字节按 Latin-1 处理，UTF-8 会变乱码）
& $py .\tools\localize_esd.py --src .\src --out .\out-gbk --map .\zh_map.json --encoding gbk
```

每次运行都会在输出目录写 `localize-report.txt`：改了多少处、哪些 label 还没翻译（照抄进 `zh_map.json` 即可）。

本次结果：**label 替换 267 处 / screen 替换 28 处 / 剩余 1 043 条未翻译**（后者绝大多数是 `CarBAPDeviceList`、`CarCANDeviceList` 里的车辆功能通道名，按需再补）。

## 四、必须先在车上验证的两件事

### 1. 字形（最关键）

`GEM.jar` 里 **没有任何字体文件**（293 个条目只有 class 和 png），文字是 J9 JVM 用自带字型画的。国行固件的中文字库能不能被 GEM 用到，只能实测。

工作区已经放了探测屏，两种编码各一份，装进主机后从绿菜单进 `ZhProbe`：

- `out\...\esd\zzprobe-utf8.esd`
- `out\...\esd\zzprobe-gbk.esd`

判读：

| 现象 | 结论 |
|---|---|
| 正常显示中文 | 用 UTF-8 产物 |
| 方框 / 空白 / 乱码 | 换 GBK 那份再试 |
| 两份都不行 | GEM 没有 CJK 字形 —— 只能走拼音/英文方案（`Skin / PI FU` 这种），或改 `GEM.jar` 里的字型（工作量大、风险高） |

### 2. 宽度截断

GEM 是按字符宽度排版：8 寸 800×480 的屏一行放不下太多双宽字符。映射表里的中文都控制在 ~15 个汉字以内；自己加词条时别超过这条线，否则会被截断或挤掉右侧的勾选框。

## 五、字符格式：十个真实雷区 + 本次实测结果

`.esd` 是给 GEM 的私有文本解析器吃的，不是给编辑器吃的。踩中下面任意一条，轻则一个屏空白，重则整支菜单消失。

| # | 雷区 | 后果 | 本次状态 |
|---|---|---|---|
| 1 | UTF-8 **BOM**（EF BB BF） | 首行 `####` 前多 3 字节，可能整文件解析失败 | 0 个文件有 BOM ✅ |
| 2 | 行尾混用 CRLF / LF | 解析器按行切，混用会导致后半段丢行 | 工具箱 23 屏全部 CRLF ✅（上游自带的 `mibstd2-hmipatches.esd` 是纯 LF，说明解析器能吃 LF）|
| 3 | 正文里出现 ASCII 双引号 `"` | 字符串提前截断，label 只剩半句 | 0 处 ✅（`sanitize` 已把全角“”压成半角 `"`，但只出现在译文内部不会触发，因为译文里我不用引号）|
| 4 | 控制字符（0x00–0x08 / 0x0B / 0x1B） | 解析器直接放弃该行 | 0 处 ✅ |
| 5 | label 里混入 TAB | 被当分隔符，label 变空 | 0 处 ✅（TAB 只出现在缩进）|
| 6 | 全角标点 `，。、；：！？（）` | 字库缺字形 → 方框；宽度按 2 格算易截断 | `out` 里 72 个字符，`out-safe` **0 个** ✅ |
| 7 | 全角数字 `０１２` | 同上，且极易漏看 | 0 处 ✅ |
| 8 | 省略号 `…` / 破折号 `—` | 字库通常没有 | `out-safe` 已换成 `..` / `--` ✅ |
| 9 | 显示宽度超屏 | 右侧勾选框被挤掉或强行截断 | 译文 122 条，**中位 18 格、最大 34 格**，>32 格的 7 条 ✅ |
| 10 | screen 名含空格 | 菜单树断裂（名字按空白切 token） | 译文菜单名全部无空格 ✅ |

**一个反直觉的实测结论**：上游 v1.5.1 自己就有 **77 条 label 超过 34 格**（`history`、`disclaimer`、`advanced` 里的长英文句）。也就是说 GEM 对"超宽"是**截断/换行**，不是报错 —— 所以宽度这关是"看不清"，不是"用不了"。真正会让整屏消失的只有 1、2、3、4、5、10。

跑体检：

```powershell
& $py .\tools\check_esd.py --dir .\out-safe\cpu\onlineservices\1\default\tsd\etc\persistence\esd --width 34
```

输出会分三段：结构/编码问题、超宽清单、全角标点统计。改完映射表重跑一遍，直到"问题"段只剩上游固有项。

### 排版规范（往 zh_map.json 加词条时照这个来）

| 规范 | 好的写法 | 别这么写 |
|---|---|---|
| 宽度 | `开启双导航` | `开启双导航功能（与车机导航并行）` |
| 标点 | `警告: 可能损坏主机` | `警告：可能损坏主机。` |
| 括号 | `(重启失效)` | `（重启失效）` |
| 省略 | `...` / `..` | `……` `…` |
| 单位/型号 | `16G 约1.5h` | `１６Ｇ 约１.５小时` |
| 数字/版本 | `v1.5` `0x0100` | 全角数字 |
| 引号 | 不用引号；必须用时用「」 | `"..."` 会截断 |



汉化只动 `cpu\onlineservices\1\default\tsd\etc\persistence\esd\` 下的 `.esd`，而 `metainfo2.txt` 里 **`SkipFileCopyChecksum = "true"`**，SWDL 不校验载荷文件 —— 所以 **`metainfo2.txt` 一个字都不用碰、也不用重算校验**。

1. FAT32 空卡，把 `out\` 里**全部内容**拷到卡根（`metainfo2.txt`、`cpu\`、`install.sh`、`toolbox\`…）。
2. 点火，插 SD1，长按 MENU → Service Mode → Software Update → 选卡 → `MIBStd2_Online_Approval`。
3. 进 GEM，看到 `MIB工具箱`（out-screens）或英文菜单 + 中文正文（out）。
4. 先用 `tools → Clean SWDL history` 清一下，别让 1556 故障码堆着。

只想更新文字、不想重装：把改好的 `.esd` 用 `customization → greenmenu` 那条路（`custom\greenmenu\` 里放 esd）导入即可，但注意官方的说法是每次工具箱升级后自定义菜单要重新导入一次。

## 六、装到车上

汉化只动 `cpu\onlineservices\1\default\tsd\etc\persistence\esd\` 下的 `.esd`，而 `metainfo2.txt` 里 **`SkipFileCopyChecksum = "true"`**，SWDL 不校验载荷 —— `metainfo2.txt` 一个字都不用碰、不用重算校验。

1. FAT32 空卡，把 `out-safe\` 里**全部内容**拷到卡根（`metainfo2.txt`、`cpu\`、`install.sh`、`toolbox\`…）。
2. 点火，插 SD1，长按 MENU → Service Mode → Software Update → 选卡 → `MIBStd2_Online_Approval`。
3. 进 GEM：`out-safe` 是英文菜单 + 中文正文；`out-screens` 是中文菜单。
4. 顺手 `tools → Clean SWDL history`，别让 1556 故障码堆着。

只想更新文字、不重装：把改好的 `.esd` 放进 `custom\greenmenu\`，用 `customization → greenmenu` 导入（每次工具箱升级后需重新导入一次）。

## 七、风险与限制

- **`screen` 名汉化是实验性的**。解析器按空白切 token，中文不含空格一般能过，但个别固件会对非 ASCII 的 screen 名报错，表现为绿菜单里这一支消失或整屏空白。出现这种情况就用 `out\`（纯 label 版）。
- **不要改结构行**：`value`、`poll`、`script` 路径、`choice` 的寄存器地址都是功能本体，改一个字就可能点到别的东西。只动双引号里的显示文本。
- **编码**：原文件是 CRLF + 纯 ASCII；脚本按 `--encoding` 写、保留 CRLF。别用记事本另存为带 BOM 的 UTF-8。
- **文件校验**：`cpu\onlineservices\1\default\hashes.txt` 里虽然列了文件摘要，但所有 `.sh` 里**没有任何地方引用它**（已验证 0 处），SWDL 也不校验载荷，所以改完直接装没问题；如果你把它备份给别人用，建议顺手更新一下这个文件，免得将来某个版本开始校验。
- **升级会覆盖**：以后把工具箱升到新版本，汉化文件会被覆盖，重跑一次脚本即可。
- **字体不可控**：如果车辆固件里压根没有中文字库给 GEM 用，这条路的终点就是拼音/英文；那是固件层面的限制，不是脚本能解决的。

---

## 八、继续补全翻译

1. 看 `out\localize-report.txt` 末尾的“未翻译的 label”清单；
2. 往 `zh_map.json` 的 `labels` 里加 `"英文原文": "中文"`（键要和原文逐字一致，含标点与大小写）；
3. 重跑脚本。

菜单项名字在 `screens` 段里，键是 `screen` 行第一个 token（如 `MIBSTD2_Toolbox`），父屏名会被脚本自动同步替换。
